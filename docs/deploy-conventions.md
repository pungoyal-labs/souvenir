# Deploy conventions — the box, the env, the pipeline

How apps deploy to the shared OCI box. Souvenir is the reference
implementation; this file is written to be followed from *another* app's
repo when migrating it onto the same box the same way. Copy the mechanism,
not the app.

## The box

- One arm64 (Ampere) OCI VM; SSH as `ubuntu`. Docker + compose plugin.
- **One app = one compose project** in `/opt/<name>`. The directory name is
  the compose project name, so containers are `<name>-app-1`, `<name>-db-1`
  and console commands stay predictable.
- **Nothing binds a public port except the proxy.** Apps publish on
  `127.0.0.1` only (`APP_BIND`); Postgres likewise. The host port
  (`APP_PORT`, `DB_PORT`) is per app — check `/opt/*/`.env on the box (or
  each repo's environment) for what's taken before picking one.
- **The shared network is `edge`** (external; created once with
  `docker network create edge`). Caddy lives on it and routes to apps by
  DNS alias. Each app joins `edge` with a **unique alias — its product
  name, never `app` or `web`**: every compose project names its service
  `app`, so the generic alias collides on a shared network. The proxy
  targets `<alias>:<container-port>`, which survives host-port changes.
- **Caddy** is a container on `edge` (`/opt/caddy`), ports 80/443(+udp),
  `/data` on a named volume (cert storage must persist — re-issuing on
  every restart hits Let's Encrypt rate limits). One site block per app:

  ```
  <domain> {
  	reverse_proxy <alias>:<port>
  }
  ```

- **Never touch another project's containers, networks, volumes or files.**
  The only host-wide command a deploy may run is `docker image prune -f`,
  which removes dangling images only — safe beside neighbours by
  definition.

## GitHub side

- Org **`pungoyal-labs`**, one repo per app, full history pushed (plain
  `git push`, not a GitHub fork). Repos are **public**: Sigstore
  attestations don't persist for private repos on the free org plan, and
  the attested build is part of the promise.
- Images: `ghcr.io/pungoyal-labs/<repo>`, tags `:short-sha` + `:latest`,
  arm64 to match the box, built and attested by CI. No registry PAT
  anywhere — the run's ephemeral `GITHUB_TOKEN` pushes, and the box pulls
  with it too.
- A GitHub **environment `oracle-cloud`** per repo is the single source of
  truth for the server's `.env`: rendered fresh on every deploy, so config
  changes are "edit the environment, redeploy" — never a hand on the box.
  The environment is **restricted to deployments from `main`**.

## Names

Environment variables (`oracle-cloud`):

| name | meaning |
| --- | --- |
| `SSH_HOST` | box IP/hostname |
| `SSH_USER` | ssh user (`ubuntu`) |
| `SSH_PORT` | optional, defaults 22 |
| `SSH_KNOWN_HOSTS` | the box's host keys, `ssh-keyscan <host>` output — the deploy pins them |
| `DEPLOY_DIR` | `/opt/<name>` |
| `APP_PORT` / `APP_BIND` / `DB_PORT` | host bindings; `APP_BIND=127.0.0.1` |
| `AUTH_URL` (or the app's base-URL var) | the public origin — the domain decision, made once |
| *(app-specific vars)* | one row here per `.env` name the app reads |

Environment secrets:

| name | meaning |
| --- | --- |
| `SSH_PRIVATE_KEY` | **set by the owner, never generated by an agent** |
| `POSTGRES_PASSWORD` | generated: `openssl rand -hex 24` — hex only, it lands inside a `postgres://` URL |
| *(app auth secret)* | generated: `openssl rand -hex 32` |
| *(feature keys)* | LLM/OAuth/etc — see the absent-not-placeholder rule |

Repo-level variable: `DOCKER_NETWORK=edge`.

Two rules that are the point:

- **Absent, not placeholder.** A secret that isn't real yet is *deleted*,
  not faked: the deploy renders every name regardless, an absent one
  renders blank, and the app must treat blank as unset — the feature fails
  closed and quiet. A placeholder fails open and loud, in front of a user.
- **Secrets are piped, never echoed.** `openssl rand … | gh secret set …`;
  a value that never appears in a terminal or log can't leak from one.

## The pipeline (`.github/workflows/ci.yml`)

Push to `main` → `verify` (lint, typecheck, tests, build) and `image`
(arm64 → GHCR, Sigstore-attested) run in parallel → `deploy` needs both.
Pull requests build the image too and throw it away — the Dockerfile
breaks on the PR, not after the merge.

The deploy step is **plain `ssh`, not an action**, because host-key
pinning is the point: the runner writes `SSH_KNOWN_HOSTS` to
`~/.ssh/known_hosts` and connects with `StrictHostKeyChecking=yes` —
a deploy cannot be redirected to a host that isn't ours. The script goes
over stdin behind an `export %q` prelude (runner env crosses the wire
without a remote shell re-parsing it) and, on the box:

1. creates `DEPLOY_DIR` if missing (sudo fallback, chowned to the user);
2. fetches `docker-compose.yml` **from the API at the exact commit being
   deployed** — the box can never drift from the repo;
3. renders `.env` from the environment (quoted heredoc, `umask 077`);
4. `docker login` with the run token, `compose pull app`,
   `compose up -d --no-build app` — which gates on the one-shot `migrate`
   service exiting cleanly;
5. **polls until the app actually serves** on
   `127.0.0.1:$APP_PORT/<unauthenticated-path>`, and fails the run with
   the container's logs if it never does — `up -d` returning is not the
   same as serving;
6. `docker image prune -f`, `compose ps`.

## The compose file

One file for dev and prod. `APP_IMAGE` picks the GHCR tag (prod, set by
CI) or a local build (dev, default). Shape:

- `db`: pinned Postgres major, loopback-only port, healthcheck, named
  volume.
- `migrate`: same image as `app`, runs migrations and exits; `app` starts
  only after it succeeds. Fresh box → schema from zero, no seed.
- `app`: `env_file: .env`, `restart: unless-stopped`,
  `ports: "${APP_BIND:-127.0.0.1}:${APP_PORT}:<container-port>"`, and:

  ```yaml
      networks:
        default: null
        edge:
          aliases:
            - <product-name>
  networks:
    edge:
      external: true
      name: ${DOCKER_NETWORK:-edge}
  ```

Dev is untouched by the shared network: `up -d db` never references it; a
full local stack needs `docker network create edge` once.

## Migrating an app with data

Souvenir launched fresh; an app that carries data adds a cutover:

1. **Audit what binds to the origin first**: OAuth redirect URIs, webhook
   registrations, cookies, CORS, anything cryptographically bound to the
   hostname (WebAuthn rp ids do not survive a domain change — decide the
   domain before touching anything else).
2. Stand the new stack up empty via a normal deploy; prove it serves.
3. **Freeze writes on the old deploy**: stop the app container, leave the
   db running. A dump taken while writes continue silently loses the tail.
4. `pg_dump` old → drop/recreate the new project's database → restore.
   Match Postgres major versions, or say so out loud first.
5. Verify at the app level (row counts, a real login, the app's own stats
   command), then flip DNS / add the Caddy site block.
6. Keep the old deploy stopped-but-intact as the rollback for a week.
   Never modify it — old repos' `main` may auto-deploy, so nothing is ever
   pushed there.

## Ops crib

```sh
# a var/secret change (from anywhere)
gh variable set NAME --env oracle-cloud -R pungoyal-labs/<repo> --body "…"
gh secret set  NAME --env oracle-cloud -R pungoyal-labs/<repo>   # value on stdin
# then re-run the deploy job, or push — .env renders per deploy

# on the box, per app
cd /opt/<name>
docker compose ps
docker compose logs --tail=100 app
docker compose run --rm migrate node scripts/<console-script>.ts
docker exec <name>-db-1 pg_dump -U <role> <db> > backup-$(date +%F).sql
```
